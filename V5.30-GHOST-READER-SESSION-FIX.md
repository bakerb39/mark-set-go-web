# v5.30 Ghost Reader Session Fix

Problem:
A previously saved Reader session (for example Crime and Punishment) can live in
IndexedDB even when that title is not present in Reading Progress. These are separate
storage systems.

Changes:
- The top **Reader** button now uses only an explicit, memory-only
  `activeReaderSnapshot` created when the user actually opens a reader during the
  current app/browser session.
- The top Reader button never reads IndexedDB.
- Persistent IndexedDB reader state is used only by **Home > Resume Last Reading**.
- Opening a Bible chapter, Bible book, Gutenberg title, EPUB, article, etc. immediately
  makes that document the active reader.
- Leaving the reader captures all reader controls and position into the active snapshot.
- Added **Forget Saved Reading** on Home when a persisted reader session exists.
  This deletes the old IndexedDB/fallback session and its lightweight metadata.
