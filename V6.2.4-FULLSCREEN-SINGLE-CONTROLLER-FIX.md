# v6.2.4 Fullscreen Single-Controller Fix

## Root cause
Each rebuilt Reader attached new document-level fullscreen listeners without
removing the listeners from the previous Reader. After repeated transitions,
detached Reader instances could all update the shared global reading position.

This explains the observed sequence:
1. First fullscreen transition worked.
2. Returning from fullscreen reset to the beginning.
3. Later transitions no longer remained synchronized.

## Fix
- Keeps only one active fullscreenchange listener.
- Keeps only one active Escape handler.
- Uses one authoritative snapshot per button transition.
- Ignores duplicate fullscreenchange restoration during button-controlled
  transitions.
- Restores after the fullscreen layout has fully settled.
- Explicitly places the pointer at the restored word before resuming.
- Persists the restored word immediately.
- Handles native fullscreen, fallback fullscreen, button exit, and Escape.
