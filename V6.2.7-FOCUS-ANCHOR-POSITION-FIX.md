# v6.2.7 Focus Anchor Position Fix

## Problem
Selecting Center Focus Anchor could reset the Reader to the beginning.

## Root cause
Focus Anchor is only a visual overlay, but its toggle rebuilt the full reader
with `prepareReaderView()`. During that rebuild, the virtualized document and
word index could temporarily return to zero before position restoration.

A second generic change listener could also persist that temporary state before
the dedicated restore finished.

## Fix
- Focus Anchor no longer rebuilds the Reader.
- Captures the canonical word index and viewport before enabling the overlay.
- Applies the overlay directly above the existing text.
- Preserves scroll position for standard reading layouts.
- Restores the correct Book Pages spread when pagination is enabled.
- Handles virtualized documents when the current word is outside the rendered window.
- Removes Focus Anchor from the generic persistence listener to prevent races.
- Immediately saves only after the correct position is confirmed.
- Continues active playback from the same word.
