# Protected Reader Behavior Contract

These behaviors are part of the protected reader architecture. They must not change unless the product owner explicitly requests a reader-behavior change.

## Pointer and keyboard interactions

1. Clicking blank space inside the reader toggles playback: running -> paused; paused -> running.
2. Clicking a rendered word in a seekable reading mode seeks to that word's reading group. It does not behave as a blank-space toggle.
3. If playback was paused before a word seek, the seek finishes paused. If playback was running, it continues running.
4. Clicking a translated word while translation is active uses the translation interaction instead of seeking or toggling playback.
5. Selecting text for Ask Mark pauses safely and must not allow the follow-up click generated by selection to accidentally restart playback.
6. Spacebar toggles playback while the reader is active, except while focus is in an interactive/editable control and except in two-column mode.

## Continuity invariants

7. Switching reading modes must preserve reading position.
8. Entering/exiting fullscreen must preserve reading position.
9. Refresh/resume must restore the saved reading position.
10. Book Pages navigation must preserve the intended cursor/viewport relationship.

## Protected implementation

- `public/reader/ReaderInteractions.js` owns the click and spacebar playback contracts above.
- Existing protected core files remain protected: `BookModel.js`, `SessionManager.js`, `ReaderEngine.js`, and `VirtualRenderer.js`.
- `scripts/audit-reader-contract.js` must pass before a release that changes reader-adjacent code.
- `PROTECTED-READER-SHA256.txt` records the approved protected implementation hashes.

Feature work in Browse, Library, Book Builder, import, AI, notes, goals, or other application areas must not edit protected reader implementation files unless an explicit reader change was requested.
