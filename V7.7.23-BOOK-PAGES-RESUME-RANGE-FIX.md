# v7.7.23 — Book Pages Resume Range Fix

## Confirmed defect

Regular text resume succeeded, but Book Pages could remain on the first spread when the saved word was inside a multi-word reading group.

Two Book Pages entry paths searched for either:

- an exact `.reader-word[data-index="savedIndex"]`, or
- an exact `.reader-group[data-start-index="savedIndex"]`.

For a three-word group covering indexes 57–59, a saved index of 58 has no exact group-start match. The resume path therefore failed to calculate the saved word's spread.

## Targeted correction

The two affected paths now use the existing canonical `restoreBookPageWordAnchor()` / `bookSpreadForWordIndex()` logic, which resolves a group when:

`group.startIndex <= savedIndex < group.endIndex`

Affected paths:

1. Saved reader-session restoration.
2. My Library/direct word-index restoration.

Regular scrolling-text restoration was not changed.

## Validation

- Root and `public/` app files are identical.
- Both JavaScript copies pass `node --check`.
- Existing reading-state audit passes.
- Book Pages tests pass for:
  - a saved word inside a multi-word group;
  - a saved word at an exact group start;
  - single-word groups.
