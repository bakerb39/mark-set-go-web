# Mark, Set, Go! v7.7.15 — Database-Backed App State

This release migrates the app's legacy `localStorage` records into the signed-in user's PostgreSQL account state.

## What is synchronized

All keys beginning with `markSetGo` or `msg-`, including reader preferences, bookmarks, notes, definitions, reading lists, progress, activity, awards, music, Bible notes, Action Center records, links, and imported-document records.

Two device/session-only keys are intentionally excluded:

- `markSetGoEmailClientIdV1`
- `markSetGoPendingLibrarySearch`

## How it works

- PostgreSQL stores each browser-storage record in `user_app_state`.
- `localStorage` remains a synchronous cache so the protected reader does not need an invasive rewrite.
- On the first signed-in load, existing local records are uploaded when the account has no matching cloud value.
- Existing cloud values take precedence and hydrate the browser cache.
- A one-time page refresh applies hydrated values to code that reads storage during startup.
- Future `localStorage.setItem()` and `removeItem()` operations are mirrored to the account API.

## Deployment requirement

Run the database migration before testing:

```bash
npm run db:migrate
```

This applies `db/migrations/003_user_app_state.sql`.

## Test

1. Deploy this branch and run the migration.
2. Sign in and allow the page to refresh once.
3. Change a reader setting, add a bookmark or note, and open a book.
4. In the console, run:

```js
await window.MarkSetGoCloud.state.load()
```

5. Confirm the returned `state` contains corresponding `markSetGo...` keys.
6. Test in a second browser or private window with the same account. The saved values should appear after the one-time hydration refresh.
